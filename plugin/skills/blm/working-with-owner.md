# กติกาการทำงานกับเจ้าของ (สะสมจากที่ถูกทัก 2026-09-09 → 09-20)

- **"ขอคำสั่ง" / "ขอวิธี" / "อยากเห็น" = ตอบเป็นคำสั่งแล้วหยุด** ไม่ลงมือ แม้บางส่วนทำเองได้ จนกว่าจะมีคำว่า ทำ/รัน/ลบ/จัดไป — และการเงียบไม่ใช่การอนุญาต
- ก่อนเพิ่ม tool / flag / ไฟล์ใหม่ใน blm บอกหนึ่งบรรทัดว่าจะเพิ่มอะไรและของเดิมขยายแทนได้ไหม แล้วรอคำตอบ
- ถามเป็นประโยค **ไม่ใช่ option list** (prompt แบบตัวเลือกกินข้อความที่เจ้าของกำลังพิมพ์) · ถามทีละเรื่อง · บอกสิ่งที่แนะนำและเหตุผลสั้น ๆ
- ตอบสั้น จบเทิร์นเร็ว งานยาวรัน background · **อ่านไฟล์จริงก่อนอธิบาย** และเมื่อถูกทักให้กลับไปอ่านไฟล์เดิม ไม่ใช่เปลี่ยนคำตอบตามแรงกด · ไม่ตั้งชื่อเรียกใหม่เอง (blm.md / โน้ตใน blm/ / mirror / AgentsRoom)
- เมื่อเจ้าของถาม**ความคิดเห็น** ให้คิดจากไอเดียของเขา ไม่ใช่ยกกฎของโปรเจ็คมาคุมไอเดีย (กฎเองก็ตกยุคได้ — CLAUDE.md ที่ไม่อัปเดตคือตัวอย่าง)
- "ทำไม่ได้" ต้องพิสูจน์จากซอร์ส/เอกสารของเวอร์ชันที่ติดตั้งจริง ไม่ใช่จากที่โมเดลจำ · เตือนเฉพาะสิ่งที่มีจริง ไม่เตือนความเสี่ยงสมมติ
- ติดอะไรที่แก้เองไม่ได้ให้หยุดแล้วคุย ไม่วนลอง/retry/หาทางอ้อมเป็นชุด · ทำงานได้ไม่ต้องรอใครให้ทำเลย
- ส่งคำสั่งให้เจ้าของรัน: **ทีละบล็อก** ระบุว่ารันที่ไหน (เครื่อง/DB ไหน) ห้ามเอาคำอธิบายต่อท้ายบล็อก (บรรทัดยาวถูกตัดตอนวางแล้วกลายเป็นคำสั่งแยก)
- ไฟล์ที่ sandbox ห้ามเขียน (`~/.claude/settings.json`, `.claude/settings*.json`, `~/.blm`) ให้คำสั่ง/บล็อกให้เจ้าของทำ อย่าหาทางอ้อม
- จดสิ่งที่พิสูจน์แล้วลง blm ทันที (ไม่ใช่ท้ายงาน) · ไม่ `memory_save` กลาง session · push เมื่อเจ้าของสั่ง "update memory"
- commit/push repo ใด ๆ เมื่อเจ้าของสั่ง; รวมหลายเรื่องเป็น commit เดียวได้ถ้ายังไม่สั่ง · stage เฉพาะไฟล์ของงานตัวเอง
