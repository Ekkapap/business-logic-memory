เป้าหมาย: ได้ไฟล์กฎ `blm.md` ที่เจ้าของยอมรับ ไม่ใช่ที่คุณเดา ทำทีละขั้น **หยุดรอคำตอบทุกขั้น** ถามเป็นประโยคธรรมดา ไม่ใช้ option list

0. เรียก `blm_status` ดู backend/store และว่ามี `blm.md` อยู่แล้วไหม (มีแล้ว = โหมดปรับปรุง เริ่มจากอ่านด้วย `blm` ก่อน)
1. **สำรวจ** เริ่มด้วย `blm_scan { path: "$ARGUMENTS" }` (ว่าง = ทั้ง root) — tool รวม ignore ทั้งสามไฟล์ นับขนาด/token ต่อโฟลเดอร์ และคืน `subProjects` (โฟลเดอร์ที่มี marker ของตัวเอง) ซึ่งแต่ละตัวคือผู้สมัครหัวข้อหลักแยก · จากนั้นเจาะรายโฟลเดอร์ตามผล
   - ใช้เครื่องมือที่มีตามลำดับ: SocratiCode (`codebase_about` / `codebase_search`) > Obsidian vault (โน้ตในโปรเจ็ค) > graphify (`graphify-out/graph.json`) > **`blm_graph`** (กราฟ import/symbol ในตัว: hubs = โมดูลแกน, clusters = โฟลเดอร์ที่เป็นผู้สมัครหัวข้อ, `query` = ใครเรียกใคร) > Glob/Grep ธรรมดา — `blm_tools status` บอกว่ามีอะไร
   - SocratiCode: ค้น**ภาษาอังกฤษก่อน** (โค้ดและ memory note เขียนอังกฤษ ผลตรงกว่ามาก ทดสอบ 2026-09-09: "authentication login" ได้ทั้งไฟล์ตรรกะหลักและ memory note 3 ใบ ส่วนคำไทยได้แต่ข้อความ UI) ใช้ภาษาไทยเสริมเฉพาะเมื่อตามหาข้อความหน้าจอ/คอมเมนต์ไทย · ผลที่เป็น `.agentsroom/memory/**` คือจุดเริ่มอ่านที่ดีที่สุด
   - **ไม่มีทั้ง SocratiCode, graphify, Obsidian** (ดูจาก `blm_tools status`): แนะนำเจ้าของติดตั้ง `tree-sitter` (`blm tools install tree-sitter` = ast-grep) เพื่อให้ `blm_graph` ใช้ AST จริง (definition + call graph) ไม่ใช่ regex · แล้ว**ถาม**เรื่อง "ความหมาย" เป็นประโยคเดียว: ให้ติดตั้ง `embedding` (Ollama + nomic-embed-text, native หรือ `--docker`) หรือให้คุณอ่านโค้ดแล้วสรุปความหมายเอง (ช้ากว่าแต่ไม่ต้องลงอะไร) — logic ข้อนี้เกิดเฉพาะเมื่อไม่มีเครื่องมือทั้งสามเท่านั้น
   - **โปรเจ็คย่อยในโฟลเดอร์เดียวกัน** (โฟลเดอร์ที่มี PLANNING.md / README / go.mod / package.json ของตัวเอง เช่น `wireguard/` ใน NPM-PORTAL) ไม่ใช่ noise ที่ต้องกรองทิ้ง — เป็น knowledge ของโปรเจ็คเหมือนกัน ให้เสนอเป็น**หัวข้อหลักแยก** ในตาราง Main Business (เช่น "Custom VPN (WireGuard, self-hosted)") พร้อมหัวข้อย่อยของมันเอง (เจ้าของกำหนด 2026-09-09) ใช้ `fileFilter` เพื่อแยกผลรายโฟลเดอร์ ไม่ใช่เพื่อตัดออก
   - ประเมินขนาดก่อนอ่าน: จำนวนไฟล์และ byte รวม ถ้าเกินราว 200k token ให้เตือนเจ้าของและเสนอแบ่ง path หรือติดตั้งเครื่องมือ (`blm tools install socraticode` ต้องมี Docker · `graphify`) ก่อนลุย
2. **เสนอหัวข้อหลัก** (Main Business) 5–12 ข้อ พร้อมเหตุผลบรรทัดเดียวต่อข้อ → รอเจ้าของแก้/ยืนยัน
3. **เสนอความหมาย** ของแต่ละหัวข้อหลัก 1–2 ประโยค → รอยืนยัน
4. **ทีละหัวข้อหลัก**: เสนอหัวข้อย่อยพร้อม block ตามแบบนี้ → รอยืนยันก่อนไปหัวข้อถัดไป
   ```
   ## <หัวข้อย่อย>
   memory: <โน้ต memory ที่มา หรือ ->
   code: <path หลัก>
   verify: <วิธีพิสูจน์ว่ากฎยังจริง — คำสั่ง/หน้า/เทส>
   updated_at: <ISO วันนี้>
   updated_by: <เจ้าของ>
   <กฎเป็นประโยคบอกเล่า 1–5 บรรทัด>
   ```
5. ประกอบไฟล์: frontmatter (`target: blm`, `mode: replace`, description "Contains …") → `# วิธีอ่าน` → `## Main Business` ตาราง (หัวข้อ | ความหมาย | จำนวนกฎ) → `# <หัวข้อหลัก>` แต่ละหัวข้อกับ block ย่อย → `# ข้อสงสัย` (สิ่งที่เจ้าของยังไม่ตอบ)
   บันทึกด้วย `blm_save { name: "blm", target: "blm", mode: "replace", description, folder: "global/conventions", content }`
   - backend none/obsidian: ไฟล์นี้คือของจริงทันที · agentsroom/custom: เป็นร่าง บอกเจ้าของว่าสั่ง "update memory" เมื่อพร้อม แล้ว `blm_sync`
6. ปิดด้วย `blm_status` แล้วบอกจำนวนหัวข้อหลัก/ย่อย และวิธีใช้ต่อ: `/blm` ตอนเริ่มวัน · `blm status` ใน terminal

โปรเจ็คใหม่ที่ยังไม่มีโค้ด: ข้ามข้อ 1 ถามเจ้าของว่าธุรกิจทำอะไร แล้วเริ่มข้อ 2 จากคำตอบ
ตอบเป็นภาษาไทย สั้น ตรง
